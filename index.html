负一屏增长战略 从资源位走向场景服务中枢

以场景化服务联动提升有效MAU，建立用户对“现在发生什么、下一步做什么”的稳定心智。

有重要变化、想知道下一步，先看负一屏。
EXECUTIVE TAKEAWAYS
核心矛盾 MAU增长不等于用户心智形成
北极星指标 月成功场景用户数

01
Executive summary

三个战略判断

负一屏真正的增长机会，不在于继续增加资源位，而在于建立系统级、可完成任务的独特价值。

01

重新定义产品角色

从“卡片与内容陈列页”升级为“当前场景的任务中枢”，帮助用户理解状态并直接完成下一步。

02

用组合场景驱动增长

日频场景负责培养习惯，状态场景负责形成回访，月频刚需负责扩大MAU覆盖，三者缺一不可。

03

从打开人数转向成功任务

页面曝光、误触和一次性Push不应成为核心成绩；应衡量有效行为、任务完成与4周重复使用。

核心决策 负一屏应优先争夺“今天的重要变化与下一步行动”心智，而不是与内容平台争夺无限浏览时长。
02
Reframe the problem

MAU问题，本质是价值闭环问题

如果用户每次进入都需要自行寻找内容或跳转多个应用，负一屏就难以形成稳定的使用理由。

当前常见模式

资源位分发逻辑

曝光→ 点击→ 跳出
  • 用户心智模糊
  • 场景之间相互割裂
  • 价值依赖运营供给
  • 打开后缺少回流理由
→
目标模式

场景任务逻辑

识别→ 完成→ 回访
  • 只呈现当前最重要事项
  • 多个服务一次联动
  • 进度持续回到负一屏
  • 形成可重复使用习惯
03
Strategic positioning

一个心智，四项产品原则

唯一核心心智 现在发生什么，下一步做什么
不是另一页信息流 不是服务商城首页 不是应用快捷入口集合
01优先级明确 首页首先回答“此刻最重要的是什么”，而不是平均分配曝光。
02完成而非跳转 把地图、钱包、日历等服务编排为一次任务，而非多个入口。
03状态持续回流 服务启动后，路线、物流、充电等进展持续在负一屏更新。
04用户可控可解释 说明场景出现原因，允许关闭、调整和纠正，避免主动服务变成打扰。
04
Metric system

用“成功场景”校准MAU质量

MAU是结果指标；真正能够指导产品决策的，是用户是否完成有价值的场景行为。

NORTH STAR METRIC

月成功场景用户数

当月至少在负一屏完成一次有效场景行为的去重用户数。页面曝光、误触和无效停留不计入。

关键状态查看 服务启动 任务 / 交易完成 进度持续追踪
当月MAU = 留存用户 + 新激活 + 沉默召回
结果层
有效MAU、DAU/MAU衡量规模与使用黏性
行为层
场景完成率、4周重复率判断是否形成稳定价值与习惯
心智层
首选率、无提示认知率衡量“遇到任务是否先想到负一屏”
护栏层
关闭率、误判率、投诉率防止以打扰和透支信任换取短期增长
05
Scenario portfolio

用场景组合兼顾规模与习惯

不能只押注单一“爆款场景”：日频、状态、月频场景分别解决不同增长问题。

使用频次：低 → 高
探索消费

丰富供给与商业转化，但不承担核心心智。

内容推荐服务发现优惠
日频锚点

覆盖广、频次高，是习惯和DAU的核心引擎。

晨间通勤日程回家
长尾服务

按需提供，不宜占据首页长期核心资源。

低频查询垂直工具
状态 / 月频刚需

以强任务和关键变化扩大MAU、形成回流。

快递停车充电账单旅行
任务价值与闭环能力：低 → 高

场景优先级模型

+用户覆盖 × 发生频率
+需求强度 × 服务闭环
+数据确定性 × 系统独特性
−隐私成本 × 打扰风险
首批验证建议同时选择：一个日频锚点、一个状态场景、一个月频刚需；实际选择需结合内部覆盖率和数据可用性。
06
Product mechanism

构建统一的场景服务闭环

外部入口只负责提示“发生了什么”，完整价值必须在负一屏内完成和持续更新。

01场景信号时间、位置、日程、设备状态
→
02识别变化判断重要性、确定性与时效
→
03轻触达锁屏、通知、手表、车机

04服务联动一次动作编排多个服务
→
05状态回流实时进展持续汇总更新
→
06下一步在合适时机推荐后续行动

07
Lifecycle growth

不同用户，不同增长任务

同一套推荐和Push策略无法同时解决激活、留存与召回，需要按生命周期匹配价值。

NEW USER

新用户

目标尽快完成第一次价值
策略选择2—3个关注场景，不做完整功能教学
关键指标首个成功场景完成率
LIGHT USER

轻度用户

目标建立第二次、第三次使用
策略用快递到柜、路线延误等高确定性状态召回
关键指标次周重复使用率
ACTIVE USER

活跃用户

目标从单场景扩展到多场景
策略今日时间轴与手机、手表、车机任务接力
关键指标人均成功场景数
LAPSED USER

沉默用户

目标以强需求完成有效召回
策略只使用账单、行程变化、空间不足等刚需事件
关键指标召回后4周留存
原则：不使用“今日精彩”“发现更多”等泛化Push制造虚假回流；优惠只能作为任务完成后的增益。
08
Mindshare building

心智来自稳定承诺与重复兑现

用户不会因为功能数量记住负一屏，只会因为某类问题被持续、稳定地解决而形成条件反射。

01统一承诺一句话定位长期稳定
02稳定结构现在—接下来—状态
03价值证明每次使用都有明确收益
04入口一致锁屏、手表、车机同语义
05信任积累可解释、可调整、可关闭
认知调研 无提示认知率

用户如何回答“负一屏是做什么的”。

任务选择 场景首选率

遇到通勤、快递等任务时，首选负一屏的比例。

行为验证 主动进入与4周复用

主动左滑、重复使用和多场景渗透共同验证心智。

10
Execution roadmap

从场景验证走向生态能力

每一阶段都设置明确验证门槛，先证明用户价值，再扩大场景和生态供给。

01
FOUNDATION

指标与数据底座

  • 统一有效活跃定义
  • 建立场景事件与归因
  • 补齐用户授权与纠错
验证门槛：数据可解释、可归因、可去重
02
VALIDATION

场景组合验证

  • 一个日频锚点
  • 一个状态场景
  • 一个月频刚需
验证门槛：有效MAU与4周复用净增
03
PLATFORM

统一产品框架

  • 现在—接下来—状态
  • 跨服务任务编排
  • 多设备任务接续
验证门槛：多场景渗透与主动进入提升
04
ECOSYSTEM

生态能力开放

  • 统一状态与动作协议
  • 服务质量与时效标准
  • 第三方元服务接入
验证门槛：供给扩大但体验质量不下降
11
Decision required

最终要建立的，不是功能认知

而是“有重要变化、想知道下一步，先看负一屏”的条件反射。

本汇报为策略框架，未使用华为内部业务基线；场景排序和目标值需结合真实覆盖率、识别准确率及用户研究进一步校准。

01
统一战略定位 明确负一屏优先服务“当前重要状态与下一步行动”，减少资源位导向的目标冲突。
02
确定首批场景组合 按照覆盖、频率、闭环、数据确定性和隐私成本完成内部评分与选择。
03
建立跨业务共同指标 以成功场景和长期复用为共同目标，避免各云服务只优化自身点击与流量。
